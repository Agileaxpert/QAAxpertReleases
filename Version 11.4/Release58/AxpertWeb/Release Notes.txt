TSK-0593 -- Enhancement:  High-Volume Data Loading in iViews/Reports
When end users attempt to load iViews or reports containing a high volume of data, the application may experience performance issues, such as request timeouts or the browser becoming unresponsive. This is particularly applicable when the Page Size is set to 0, which causes all records to be loaded without pagination.
To address this issue, the application has been enhanced to initially load only a minimal number of records when a high-volume dataset is detected. This helps improve application responsiveness and prevents unnecessary browser or server resource consumption.
Users can still export the complete dataset to Excel, PDF, or Word when the full data is required.
Note: If a specific report requires all records to be displayed without pagination, the required Page Size (Fetch Size) can be configured through the Developer Options.
However, setting an excessively large Fetch Size, such as 50,000 or 100,000 records, may significantly degrade application performance. Therefore, the Page Size/Fetch Size should be configured intelligently by the Solution Developer based on the actual business requirement and expected data volume.

TSK-0690 -- Enhancement: React Page Support in Plugin Custom Code
 Notes: 1. A new 'React Pages' option has been introduced in the 'Custom Plugins' page to enable users to create React pages.
        2. React page files are stored in both: 
            a. The 'database'
            b. The 'Project folder', under the 'ReactPages' folder located in the 'AxpertWeb application code folder'.
        3. To load React pages from the 'Menu' or 'Global Search', the following IIS configuration is required:
           a. Create a new application pool named 'AxReact' and set Managed Runtime Version to 'No Managed Code'.
           b. Create a new site/application named 'AxReact' under the 'AxpertWeb application/site'.
           c. Assign the 'AxReact' application pool to this application.
           d. Set the physical path to the 'ReactPages' folder available under the AxpertWeb application code folder.
        4. The 'Custom Pages' option has been withdrawn from the Options menu and its functionality has been moved to the 'Custom Plugins' page.

TSK-0688 –- Enhancement: Provision to Update an Existing Record Without Using Record ID in AXPUT = true API
The **AXPUT API** has been enhanced to support updating existing records without requiring `axp_recid`.
* `keyfield`, `keyvalue`, and `axrow_action` are mandatory for each row.
* `axp_recid` is now optional.
* If `axp_recid` is provided, it must be valid; otherwise, it should be excluded.
* When `axp_recid` is not provided, `keyfield` and `keyvalue` are used to identify the existing record.
* The same `axp_recid` approach must be followed consistently across all DCSs and rows.

TSK-0668 –- Enhancement: Additional Details to be Returned by AxGet API
The **AxGet API** now returns the following additional nodes:
* `createdon`
* `createdby`
* `modifiedon`
* `modifiedby`

TSK-0698 –QA- Data Not Saving with AXPUT = true Due to Validation Errors
The issue was reported when using the **CachedSave Consumer Worker Service**, where `AXPUT = true` invokes the ARM AxPut API.
The following issues have been fixed:
* **Date Validation:** Handled date validation using `ClientDateFormat` when fetching date values.
* **Numeric / ID Fields:** Handled Numeric and ID fields properly during MDMap execution for SQL-related operations.
* **Duplicate Check:** Fixed the Duplicate Check issue by handling the conditions properly.
* **Picklist Validation:** Fixed Picklist execution where valid data was incorrectly reported as an invalid selection.
* **Normalized Fields:** Reset `IDValue` properly during normalized field processing.
* **Multiple Picklist Fields:** Fixed the **"A command is already in progress"** error when multiple Picklist fields are processed sequentially by properly handling asynchronous execution using `await`.
